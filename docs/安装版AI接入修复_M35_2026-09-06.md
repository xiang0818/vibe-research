# M35 · 安装版 AI 接入与首次登录修复

## 本轮来源与边界

Simon 授权继续推进剩余缺口，随后提供安装版快捷接入报错截图，并确认点击的是「Codex订阅版」。本轮优先修复这个首次使用阻塞，不改已认可视觉、默认关闭 Agent、保存来源与用户数据隔离。

活动仓库仍是 `vibe-research-agent-Codex` / `feat/dual-engine`，HEAD `2ed80acd`。保留原有未提交增量，不暂存、不提交、不推送、不发布。未复制个人 Codex 登录，也未改全局配置或记忆。

## 事实与根因

- M34v2 原生 App 本轮重新启动后，全来源只读探针 HTTP 200，约 7.67 秒；Claude 2.1.261 与 WorkBuddy 2.137.1 均返回 ready。上一轮二者失败本轮未复现，不能宣称其环境根因已解决。
- 同一安装版 Codex 0.153.4 明确返回 not_authenticated。它使用产品专用 `~/.vibe-research-desktop/codex-home`，不会自动继承 Codex App 或开发仓库认证。这与用户确认点击 Codex 后的截图吻合。
- 旧弹窗没有原地登录按钮，失败信息不标来源。旧后端还会把 Claude 状态读取失败/坏 JSON/超时当成未登录；Codex 官方 CLI 对「未登录」与「读取失败」都可返回 exit 1，必须区分输出。
- 前端预检本来等待全部三家供应商；某个未选择的 CLI 缓慢也会延迟当前接入。

## 改动

1. 快捷弹窗标明失败来源；Codex 认证未完成时显示独立产品登录说明、「登录 Codex」「登录后重新测试」，复用既有官方登录接口。启动登录不保存配置，测试成功后才保存。关闭弹窗取消前端请求；已经启动的官方登录按原生命周期完成/超时，不宣称关闭弹窗会撤销授权。
2. `/local-agents?provider=cli-codex|cli-claude|cli-codebuddy` 只检测指定来源；无参数仍返回全部三家，非法来源拒绝。
3. Claude 显式认证 JSON 才判断登录状态；坏输出/启动异常/超时是 probe_failed。Codex 只有 exit 1 且 stderr 存在独立行 `Not logged in` 才判未登录，其余错误保留检测失败。探针错误不回显账号/路径/底层原文。
4. Codex/Claude 只读版本、帮助、认证探针超时改用 SIGKILL；不改模型运行的权限或时限。
5. 前端分别保留未安装、检测失败、未登录提示；普通连接错误不再统统映射为认证错误。
6. 翻译与引导工具遗漏的取消信号已补齐；已取消的预检在发送请求前退出。
7. 新本地构建标识 M35/build35；产品版本仍为 1.0.4，不代表公开 v1.0.4 已包含这些本地改动。继续保留 M34v1/v2。
