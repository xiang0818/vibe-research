## 本轮修复

1. Python 运行依赖固定为 40 项精确版本，并使用下载哈希安装、安装后依赖一致性检查。
   包内保留锁文件与哈希；依赖清单使用 name==version，避免把构建机临时 wheel 路径带进包。
   这不等于位级可复现：独立 Python 发行归档、sdist 隔离构建依赖与 Apple 编译工具链未全部锁哈希。
   方法依据：[uv 锁定依赖说明](https://docs.astral.sh/uv/pip/compile/)。
2. 含空格的产品根、数据根或解释器路径默认使用 controlled_mcp；显式选择 shell_hooks 时仍保留旧路径守卫。
   不修改官方 Codex 源码，不改变用户所选 AI 来源，不放宽 Shell 安全扫描。
3. 更新两个生产间接依赖：fast-uri 3.1.7、qs 6.16.0；npm 生产依赖扫描降为 0 项已知漏洞。
   修复依据：[fast-uri 公告](https://github.com/fastify/fast-uri/security/advisories/GHSA-f65p-4m7j-42xc)、
   [qs 公告](https://github.com/ljharb/qs/security/advisories/GHSA-4mjr-xmp4-gh2g)。
4. 回测新增 `execution_fees` 与 `fill_count`，从引擎已有不可变成交记录确定性汇总。
   包括期末强制平仓，只记实际扣除费用一次；不改交易、现金、收益算法。
   结果带计价币种、费用已计入净值说明；trade_count 明确是平仓记录数，不冒充买卖执行次数。
   历史结果缺字段仍缺失，不捏造为 0。
5. 报告访问、运行详情和列表共用同一终态校验口径。
   complete/incomplete 但退出码、结束时间、gate 或 final_errors 不一致时显示“未通过校验”，
   不再出现“完成”徽章与不可读草稿矛盾。旧记录缺省 gate/final_errors 的兼容规则保留。
6. 研究归档名称兼容真实取数器的 `extra.name`，证据名称优先；只作为列表元数据，
   不升级为研究证据，也不从模型摘要猜公司名。
7. README 中英文、安装说明、指令发现链与发布清单更新；数据上游对账见 `datasources/UPSTREAM.md`。
   未整包移植 a-stock-data v3.8.0 新功能，未合并开放 PR 或冒称全部上游代码已对齐。
