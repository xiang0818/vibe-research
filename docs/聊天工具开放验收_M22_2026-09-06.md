# M22：普通 Agent 对话接通联网与业务工具

2026-09-06，本地开发增量，未提交、未推送、未发布。活动副本 `vibe-research-agent-Codex`，分支 `feat/dual-engine`，HEAD `2ed80acd`。

## 原因与结果

用户截图中的“没有工具、不能联网”来自产品旧的普通对话路径：提示词声明没有工具，启动配置也禁用了工具，并非 Claude Code 订阅无法联网。用户要求“全部打开，不能做这个限制”。

现在首页和浮动聊天共用可调用工具的 Agent 对话链。无需重新选择模型或切换到研究页才能搜索、读网页、取数或计算；保持当前用户选择的 AI 来源。明确关闭 Agent 的直连模式仍保持原语义，接入探针、内部翻译等受限子任务不因本次修改获得额外工具。

开放 13 个产品工具入口：联网搜索、网页正文、数据源发现、实时取数、研究列表、任务状态、报告读取、证据查询、知识档案、台账读取、分析工具目录、确定性计算/回测、完整研究提案。

完整研究通过聊天提出后，由真实界面显示目标和范围，用户确认一次才启动；返回真实任务编号，随后可以在聊天中查询进度。模型不能自行调用确认接口。日常只读工具无需逐次确认。研究提案绑定数据目录与所选来源，十分钟有效、一次性使用，不覆盖已有任务。

本轮没有开放任意 Shell、凭据文件读取、全盘访问或自动改台账；没有删除密钥保护、来源选择、证据纪律和投资动作建议边界。这些不妨碍上述联网与业务能力。

## 实现与来源

- `assistant_turn.ts` 提供原生工具循环、同来源/资料范围的有限历史、取消和资源释放；`assistant_bridge.ts` 与 `assistant_tools_mcp.ts` 将现有服务以本轮临时 MCP 暴露给 Codex 和本地订阅 CLI。
- `service.ts` 复用已有注册表、取数、工具、报告、知识层和研究启动服务。`core/retrieval_cli.py` 复用已有 Exa/Jina 检索实现，不新建另一套抓取器；命中查询端点不等于搜索结果一定相关。
- 网页检索服务响应保留在 `.local/chat-web/<随机编号>.json`，模型获得摘录、来源、归档引用与哈希。它是检索服务响应的归档，不冒充目标网站原始 HTTP 字节；截断和最终 URL 未知的标记保留。
- 界面显示服务器生成的“本轮工具记录”。失败不显示成成功；`partial` 仍保留已取得内容，由业务结果说明缺口。研究提案显示“准备研究”，不能提前标成“已启动”。
- 计算目录新增真实函数参数、默认值和 `{fn,args}` 请求形状，公式不变。网页入口复用已有 UTF-8 标准输入输出修复，避免中文 Windows 管道编码影响 JSON。
- `search-first` 促使本轮复用现有工具和 MCP 接口；`codex-delegate` 执行独立审查；`browser-harness` 验证用户真实页面；没有使用 WorkBuddy 额度。

## 真实运行

1. **Codex / GPT-5.6 Sol 联网**：实际 HTTP `/chat`，会话 `m22-live-sol`，约 43.9 秒。搜索一次、读取三个官网页面，均有成功工具记录；回答引用真实链接，没有读取台账或启动研究。
2. **Codex 数据与计算**：会话 `m22-live-sol-data`，约 76.1 秒。发现端点并实际取数，保留数据期间和证据；计算最终成功。但初版目录缺少参数契约，模型曾尝试四次错误参数，不能把该轮写成零失败。
3. **计算修复复验**：最新后端，会话 `m22-live-sol-calc-final`，约 39.2 秒。依次查看工具、查看计算目录、调用增长率，三次记录全部成功、没有参数重试，返回确定性显示串 `20.00%`。输入仅测试数 120/100，无投资数据或研究任务。
4. **Claude Code 实际页面**：保留用户原有选择，从 `http://127.0.0.1:5940/` 首页发送读取官网请求。实际返回官网摘要与来源，显示“本轮工具记录：读取网页”，不再宣称没有工具或不能联网。截图 `/tmp/vra-m22-claude-web.png`（临时预览路径）。

页面、前端和当前后端均使用活动仓库；后端已重启载入最终修复。5930 属于项目 39，没有停止或改动。没有复制个人 Codex 登录态，没有替换用户的 Claude Code 选择。
